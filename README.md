# Supabase Lite

Облегчённый self-hosted Supabase на Docker Compose. Цель — переносимый, воспроизводимый стек с **семью сервисами**: PostgreSQL, Auth (GoTrue), PostgREST, Realtime, Storage, Edge Functions и Envoy API Gateway.

Отключены по умолчанию: Studio, Postgres Meta, imgproxy, Supavisor.

> **Состояние проекта: подготовка шаблона. Пока не готов к установке.** Рабочая конфигурация развёрнута отдельно на VDS, но ещё не перенесена и не проверена в этом репозитории. Не используйте команды из этого репозитория для замены работающего Supabase.

## Что добавлено в подготовительный PR

- `.env.example`: только пример имён переменных и заведомо неработающие значения.
- `scripts/preflight.sh`: read-only проверка Docker/диска/прав без запуска сервисов.
- `scripts/validate-template.py`: проверка шаблона без секретов.
- `.github/workflows/static-validation.yml`: статическая проверка файлов.
- [Порядок безопасного выпуска v0.1](docs/RELEASE_ACCEPTANCE.md).

**Внимание:** этого недостаточно для развёртывания: переносимый Compose, системный bootstrap и clean-room тесты ещё не сделаны.

## План релиза v0.1

1. Получить **обезличенную** копию двух Docker Compose файлов, список закреплённых image tags и перечень **имён** переменных окружения с существующего VDS.
2. Убрать адреса конкретного проекта, пароли, JWT-секреты, ключи OneSignal, токены и идентификаторы окружения.
3. Добавить `.env.example`, генератор уникальных секретов, валидатор конфигурации, установщик с безопасной проверкой конфликтов.
4. Добавить HTTPS через существующий reverse proxy или отдельный пример Nginx, без перезаписи действующей конфигурации.
5. Проверить чистую установку на отдельном тестовом Docker project и томах, health checks, перезапуск, резервное копирование и восстановление.
6. После проверок выпустить версию `v0.1.0` с точным списком проверенных образов.

## Безопасность

- Не коммитить реальные `.env`, приватные JWT-ключи и дампы БД.
- Docker volumes и данные Storage остаются локальными на сервере; репозиторий не является их резервной копией.
- Шаблон не должен использовать неизменяемые общие пароли или подписи JWT между установками.
- Перед подключением production требуется проверенное восстановление из отдельной резервной копии.
