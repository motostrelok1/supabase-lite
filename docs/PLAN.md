# План: Supabase Lite v0.1

## Текущий эталон (зафиксировано со слов оператора)
- Ubuntu 24.04; Docker Compose.
- Сервисы: PostgreSQL, GoTrue, PostgREST, Realtime, Storage, Edge Runtime, Envoy.
- Выключены: Studio, Meta, imgproxy, Supavisor.
- Образ PostgreSQL: `supabase/postgres:17.6.1.136`; теги остальных образов **не подтверждены**.
- На исходном VDS используются `/opt/supabase/docker-compose.yml` и `docker-compose.override.yml` совместно. Этот репозиторий пока не содержит проверенной копии этих файлов.
- Необходимо проверить запуск через `env -i PATH="$PATH" HOME="$HOME" docker compose -f docker-compose.yml -f docker-compose.override.yml ...`: в исходной среде `source .env` приводил к проблемам.

## Реализация
- [ ] Безопасно экспортировать и проверить исходные Compose-файлы. Не переносить реальные значения секретов, паролей, токенов или ключей.
- [ ] Закрепить теги/дигесты каждого сервиса и валидировать `docker compose config` с тестовыми секретами.
- [ ] Создать `.env.example` по фактическим переменным стека; подготовить генератор **новых** JWT и паролей.
- [ ] Добавить `install.sh`: интерактивный домен, проверка портов/ресурсов, изоляция project name и volumes, защита существующей установки.
- [ ] Подготовить Nginx HTTPS как отдельно подключаемый пример (не менять действующие сайты).
- [ ] Проверить чистый запуск на тестовом сервере/в изолированной среде.
- [ ] Добавить backup PostgreSQL + Storage, контроль целостности и тест восстановления.
- [ ] Документировать обслуживание, обновление образов, мониторинг, ресурсы и откат.
- [ ] Проверить лицензии и упоминание Supabase, не позиционировать сборку как официальный дистрибутив.
- [ ] Отдельный релиз `v0.1.0` только после всех проверок.

## Ограничения безопасности
- Никакого `docker compose down -v` в автоматических скриптах.
- Никогда не использовать общий заранее заданный JWT secret или пароль.
- Не переносить из production `.env`, Storage, дампы БД или TLS-ключи в публичный GitHub.
- Не запускать исходный cron или Edge Functions, отправляющие уведомления, при тестовом восстановлении.
- Сборка инфраструктуры и перенос пользовательских данных — отдельные процедуры.
